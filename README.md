# Daylight

A private Android companion for intention, inspiration, and reflection. Native Kotlin and Jetpack Compose; Android 8.0 (API 26) and later. No account, network permission, analytics, ads, or cloud service.

**Current status:** source implementation is present, but build and runtime verification are blocked by unavailable JDK/Gradle downloads in this environment. No verified APK has been produced. See [VERIFICATION.md](VERIFICATION.md) for the exact checks and blockers.

## Open and build

Open this directory in Android Studio. Use JDK 17, Android SDK Platform 35, and Build Tools 35.0.0. Gradle 8.11.1 is pinned by the wrapper, with Android Gradle Plugin 8.9.2 and Kotlin 2.1.20.

```powershell
# Windows; configure JAVA_HOME and ANDROID_HOME first
.\gradlew.bat assembleDebug testDebugUnitTest lintDebug

# Or use the optional project-local tools
.\scripts\build.ps1
```

```sh
# macOS / Linux
sh ./gradlew assembleDebug testDebugUnitTest lintDebug
```

The installable debug APK is generated at `app/build/outputs/apk/debug/app-debug.apk`. Install it with Android Studio's Run button or `adb install -r app/build/outputs/apk/debug/app-debug.apk`. This is a personal debug build; a distributable release requires your own signing key. Do not commit signing credentials.

`scripts/download_toolchain.py` optionally downloads official Windows JDK, Gradle, and SDK command-line distributions under the ignored `.tools` directory. It resumes interrupted archive segments and ZIP-tests archives before extraction. Android Studio's SDK Manager is the usual way to install SDK packages. No machine-wide settings are changed by the script.

## Product

- **Home:** daily inspiration, real checklist progress, upcoming reminder, daily forms, recent entries, and quick actions.
- **Library:** manual content creation, editing, deletion, category filtering, search, favorites, and enable/pause controls. Quran fields include verse, surah, verse number, translation, source, and reference. Hadith supports source and reference. Religious text is never generated, corrected, or seeded.
- **Forms:** seven question types, ordering, required fields, local response history, and editable response reviews. Optional evening reminders link to the exact submitted response.
- **Schedule:** daily fixed times, intervals of at least 15 minutes, deterministic randomized daily windows, minimum spacing, previews, pause/resume, and next occurrences.
- **Settings:** system/light/dark themes, notification access, sound/vibration, quiet hours, JSON export/import, and rotation reset.
- Global search covers library titles/text/categories/sources, forms, and reflection text.

The optional starter form contains non-religious daily goals. Explicitly labeled sample motivation can be added from Settings **only in debug builds**. Production content is otherwise empty.

## Architecture and project structure

Single app module, with a small manual application dependency container instead of a DI framework. This keeps the personal app easy to maintain without sacrificing separation of concerns.

```text
app/src/main/java/com/daylight/app/
  DaylightApplication.kt        Application container and recovery work
  MainActivity.kt               Activity and notification routing
  data/
    Models.kt                   Normalized Room entities
    Database.kt                 DAOs, relationships, converters
    Repository.kt               Transactional form/content operations
    Backup.kt                   Versioned validation and additive import
  domain/
    SchedulePlanner.kt          Pure, clock/zone-injected planning logic
    FormLogic.kt                Validation, progress, notification summaries
  notifications/
    NotificationEngine.kt       Persisted queue + Android AlarmManager
    Receivers.kt                Alarm, boot/time recovery, notification actions
  ui/
    DaylightViewModel.kt        Flow state and user-facing operation results
    App.kt, Theme.kt             Navigation, onboarding, appearance
    *Screen.kt                  Dashboard and complete feature screens
app/src/test/                   JVM and Robolectric tests
app/src/androidTest/            Real-device navigation smoke test
app/schemas/                   Room schema snapshots generated by KSP
```

Room flows feed a lifecycle-aware ViewModel and Compose UI. Writes use coroutines and Room's transaction dispatcher. Navigation Compose owns routes and the bottom tabs. Form and content drafts use saveable state for activity recreation; unsaved backup-import review intentionally requires selecting the file again after process recreation. Saved user data survives process death in SQLite.

## Database

Separate tables hold content, forms, questions, responses, answers, reflections, schedules, preferences, and reminder occurrences. Foreign keys cascade form deletion through its questions, responses, answers, reflections, and form schedules. Indexes cover relationships, response dates, category/rotation queries, and occurrence state/time. UUIDs identify exported records.

Answer rows snapshot question text, type, options, and order. Changing a form template does not rewrite historical submissions. Only small scalar collections (question choices, selected choices, and daily fixed times) use JSON column converters; the database is not one JSON blob.

Checklist completion is checked options divided by total checkbox options. A form with no checkbox questions uses answered questions divided by all questions. A required checkbox needs at least one selected choice; keep it optional if an entirely unchecked morning plan should be valid.

The initial schema is version 1. Future database changes must add explicit Room migrations; destructive fallback is not enabled.

## Reminders and recovery

The planner materializes an eight-day queue into Room. One immutable, explicit PendingIntent registers the next occurrence with AlarmManager. After delivery, the engine claims the occurrence and rebuilds the queue. There are no in-memory timers.

- With Android's precise-alarm access, the engine uses `setExactAndAllowWhileIdle`; otherwise it uses `setAndAllowWhileIdle` and communicates flexible timing in the UI. A permission race falls back to the inexact path.
- Boot, package replacement, clock changes, timezone changes, and exact-alarm access changes enqueue unique WorkManager recovery. A 12-hour recovery job provides a second chance to rebuild schedules. Opening the app also rebuilds them.
- Random times are derived from the schedule ID and local date, so reopening or rebooting does not shuffle the same day's reminders. A suffix-capacity algorithm chooses only feasible randomized slots. Spacing uses elapsed time, including across DST changes.
- Fixed and interval reminders use local wall-clock time. A nonexistent DST time moves forward with Java time's zone rules; repeated fall-back times fire once. Submission reviews are one-shot instants calculated when saved. Quiet hours may defer these reviews until rest ends.
- Quiet-hour content occurrences are omitted. Impossible random schedules are paused; the UI shows their disabled state. When occurrences collide within one minute, only one is kept, with a review preferred at identical times. A standalone schedule preview describes its own times before collision suppression.
- Notifications rotate enabled content by unseen first, then oldest shown. Empty categories produce no notification. Favorites do not alter rotation order.
- A late alarm emits at most one reminder, and only within an hour of the planned time. Recovery skips elapsed occurrences rather than sending a backlog.
- Expanded review notifications contain the saved checklist. Open actions navigate to the exact response. Content notifications offer Open, Favorite, and Mark as read. Notification IDs and immutable PendingIntents are stable per occurrence.

No Android app can guarantee delivery under every manufacturer battery policy. Force-stop disables delivery until the app is reopened. Revoking precise-alarm access may cancel existing Android alarms; reopening the app or the periodic recovery job restores flexible alarms. WorkManager recovery itself may be delayed by the OS. Enabling notifications later does not replay previously skipped reminders. The system may truncate long notification text; the full original is always available inside the app. A process failure between claiming an occurrence and displaying it can lose that occurrence; claiming prevents duplicate bursts.

Official behavior references: [Android alarm scheduling](https://developer.android.com/develop/background-work/services/alarms), [notification runtime permission](https://developer.android.com/develop/ui/views/notifications/notification-permission), and [persistent background work](https://developer.android.com/develop/background-work/background-tasks/persistent).

## Permissions and privacy

| Permission | Reason |
| --- | --- |
| `POST_NOTIFICATIONS` | Show reminders on Android 13+. Requested only from the explained notification controls. |
| `SCHEDULE_EXACT_ALARM` | Optional user-granted access for closer reminder timing. Flexible reminders work without it. |
| `RECEIVE_BOOT_COMPLETED` | Rebuild alarms after a device restart. |
| WorkManager's merged wake-lock/network-state permissions | Background job infrastructure; no Internet permission is requested. |

Backup uses Android's Storage Access Framework; no broad storage permission is needed. Android cloud auto-backup is disabled. Notifications use private lock-screen visibility, subject to the user's system preferences. Exported files are plaintext and are private only to the extent that the selected storage location is private.

## Backup behavior

Export is a consistent transactional JSON snapshot, schema version 1, containing settings and all user-authored data. Runtime occurrences are regenerated rather than exported.

Import reads at most 10 MB, validates the version, identifiers, enums, relationships, questions, answers, and schedule ranges before mutation, and presents a confirmation with record counts. It then adds new content and new form trees in one transaction. Existing IDs and existing form trees are skipped, including associated history; conflicting child identifiers reject the entire import. This is an additive archive import, not a two-way sync.

Existing settings are preserved (exported settings remain available in the file). Imported schedules are paused. Imported responses do not schedule old evening reviews. No existing record is silently overwritten. Reimporting the same backup is idempotent. Keep regular exports before uninstalling the app or clearing its storage.
